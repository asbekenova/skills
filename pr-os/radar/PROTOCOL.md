# Протокол радара: репозиторий asbekenova/skills

Общий шаг для всех радаров: «Визуальный радар блога» (ноябрь, декабрь, еженедельный с января) и «Радар Telegram-каналов».
Радар читает этот файл в начале каждого запуска и делает то, что здесь написано. Если файл противоречит промпту радара, главнее промпт.

## 0. Подключение (первым делом)

1. `add_repo` с owner `asbekenova`, repo `skills`, access `push`.
2. Клонировать ветку pr-os:
   `git clone --depth 1 -b pr-os https://github.com/asbekenova/skills /home/user/skills`
3. `cd /home/user/skills/pr-os/kit && npm i --no-audit --no-fund` (ставит шрифты и roughjs).
4. Если что-то из этого не прошло, напишите об этом в отчёте одной строкой и работайте по старой схеме, без репозитория.

В main не коммитить: там код CLI от Vercel, его обновляют из оригинала. Вся наша работа живёт в ветке `pr-os`.

## 1. Поиск новых скиллов

Переменные для каждой команды CLI: `NODE_USE_ENV_PROXY=1 DISABLE_TELEMETRY=1`. Без первой поиск в облаке возвращает пустоту.

```bash
NODE_USE_ENV_PROXY=1 DISABLE_TELEMETRY=1 npx -y skills@1.9.0 find "<запрос>"
```

Запросы на выбор, каждый запуск 3–4 разных:
- визуальный радар: `remotion`, `motion graphics`, `kinetic typography`, `video editing`, `ffmpeg`, `captions subtitles`, `stop motion`, `collage`, `instagram carousel`, `reels`, `rough sketch animation`, `lottie`;
- Telegram-радар: `instagram`, `content plan`, `copywriting russian`, `medical marketing`, `clinic`, `social media`, `brand voice`, `airtable`, `make automation`.

Посмотреть состав репозитория со скиллами, ничего не ставя:
```bash
NODE_USE_ENV_PROXY=1 DISABLE_TELEMETRY=1 npx -y skills@1.9.0 add <owner/repo> --list
```

## 2. Проверка перед тем, как предложить

Скилл проходит, только если выполнены все условия:
- **Источник.** Официальный автор (`anthropics`, `remotion-dev`, `vercel-labs`, `microsoft`, `heygen-com` и подобные) или репозиторий от 100 звёзд на GitHub. Остерегайтесь клонов: одинаковые скиллы под разными владельцами (например, десятки `*/superpowers@ai-video-generation`) это перезаливы, установки там накручены. Берите оригинал или ничего.
- **Установки.** От 1 000. Меньше только у официального автора.
- **Содержимое.** Прочитайте SKILL.md и все скрипты целиком (склонируйте репозиторий в отдельную пустую папку и читайте, ничего оттуда не запуская). Отклоняйте, если скрипт шлёт данные наружу, просит ключи, ставит что-то глобально, скачивает и исполняет код, или если скилл учит генерировать людей, голос, текст на картинках ИИ или автопубликацию (жёсткие правила блога).
- **Польза.** Закрывает реальную задачу PR_OS, а не дублирует то, что уже есть. Перед этим сверьтесь со списком скиллов сессии и с папкой `.claude/skills/` в этом репозитории. Дубль: пишите «уже есть: <скилл>».
- **Не платный контент** клубов и курсов.

## 3. Установка (не больше 2 скиллов за запуск)

Ставится в отдельную ветку, не в pr-os. В сессиях ничего не включается, пока Азиза не одобрит.

```bash
cd /home/user/skills
git checkout pr-os && git checkout -b radar/skill-<имя>-<ГГГГ-ММ-ДД>
NODE_USE_ENV_PROXY=1 DISABLE_TELEMETRY=1 npx -y skills@1.9.0 add <owner/repo> --skill <имя> -a claude-code --copy -y
```

CLI кладёт скилл в `.claude/skills/<имя>/` и записывает версию в `skills-lock.json`. Дальше:
1. Добавьте строку в `pr-os/radar/skills-log.md`: дата, скилл, источник, установки, зачем, что проверено.
2. Коммит: `radar: скилл <имя> для <задача>`, затем
   `git -c push.negotiate=true push -u origin radar/skill-<имя>-<дата>`.
3. В отчёт: одна строка со ссылкой на сравнение
   `https://github.com/asbekenova/skills/compare/pr-os...radar/skill-<имя>-<дата>`.
   Азиза смотрит и нажимает «Create pull request», затем «Merge». После слияния скилл подхватывается в каждой сессии, к которой подключён этот репозиторий.

Pull request сами не открывайте. Скрипты установленного скилла во время радара не запускайте.

Если скилл хорош для всех её сессий, а не только для работы с репозиторием, отметьте это в отчёте: его можно ещё и загрузить в аккаунт как личный скилл (Telegram-радар делает это через propose_skills).

## 4. Монтажный набор и библиотека (визуальный радар)

- Мини-тест собирайте только из набора: `pr-os/kit/template.html` копируете в `pr-os/library/<ГГГГ-ММ-ДД>-<название>/scene.html` и меняете render(t). Цвета, шрифты, бумагу и безопасную зону не переписывайте, они в `kit/brand.css`. Хелперы анимации лежат в `kit/ease.js`.
- Проверка кадров: `cd /home/user/skills/pr-os && node kit/render.mjs library/<папка>/scene.html --preview`. Посмотрите PNG в `keyframes/`: красная рамка показывает безопасную зону.
- Рендер: `node kit/render.mjs library/<папка>/scene.html`, получится `preview.mp4` в той же папке. Отправьте его через SendUserFile.
- Рядом положите `notes.md`: идея, источник, рубрика, что проверяем, и пустое поле «Оценка Азизы».
- Добавьте строку в `pr-os/library/INDEX.md`.
- Коммит в ветку `pr-os`: `library: <название>`, затем `git -c push.negotiate=true push origin pr-os`. Тест сохраняется всегда; если Азизе не понравится, она поставит оценку, и следующие запуски учтут это.
- Если улучшили сам набор (новый хелпер в ease.js, полезный приём в шаблоне), это отдельный коммит `kit: ...` с объяснением в теле.

Если push не прошёл, не повторяйте больше двух раз; напишите в отчёте, что тест лежит только в сессии.

## 5. Учёт обратной связи

Перед поиском прочитайте `pr-os/library/INDEX.md` (колонка «Оценка») и `pr-os/radar/skills-log.md` (колонка «Решение»). Что отклонено, не предлагайте снова; что понравилось, развивайте.
